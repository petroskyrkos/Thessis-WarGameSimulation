# War Game Simulation — Project Context

Μεταπτυχιακή διπλωματική (MSc Web Intelligence). Agent-based simulation ενός war game
Ελλάδα–Τουρκία. Ο **τελικός** ερευνητικός στόχος είναι η σύγκριση του Mosaic Warfare concept
(DARPA/RAND) με κλασική δομή δυνάμεων.

> **Τι χτίζουμε ΤΩΡΑ: Φάση 1, κλασικές (μονολιθικές) δυνάμεις.**
> Κάθε platform κουβαλά το δικό του πλήρες σετ ικανοτήτων, όπως μια συμβατική διάταξη μάχης.
> **Δεν υπάρχει κώδικας Mosaic σε αυτό το build** και δεν μπαίνει μέχρι να ολοκληρωθεί και να
> επικυρωθεί πλήρως η Φάση 1. Το «Mosaic» στον τίτλο της διπλωματικής δεν σημαίνει ότι η
> πρώτη υλοποίηση είναι mosaic — είναι το αντίθετο: το κλασικό baseline είναι αυτό με το
> οποίο θα συγκριθεί αργότερα το Mosaic.

Η γλώσσα συνεργασίας με τον χρήστη είναι **ελληνικά**. Ο κώδικας, τα comments, τα ονόματα
μεταβλητών και τα commit messages είναι **αγγλικά**.

## Τι μελετάμε στην πραγματικότητα

**Οι απόλυτες τιμές δεν είναι το αντικείμενο.** Αν ένα αεροσκάφος πετάει 800 ή 1000 km δεν
αλλάζει η ποιοτική συμπεριφορά του συστήματος. Σημασία έχουν οι **σχετικές** διαφορές
απέναντι στον αντίπαλο.

Οι high-level παράμετροι του προβλήματος είναι **ρυθμοί**:

1. ρυθμός παραγωγής όπλων
2. ρυθμός ξοδέματος όπλων
3. ρυθμός απωλειών στο μέτωπο
4. ρυθμός αναπλήρωσης μονάδων που χάνονται

Αυτοί είναι οι θεμελιώδεις παράγοντες του παιγνίου και αυτό που ερευνάται. Κάθε σχεδιαστική
απόφαση κρίνεται με το κριτήριο: **διευκολύνει τη μελέτη αυτών των ρυθμών;**

Το δεύτερο ερευνητικό ερώτημα: **πώς αλλάζει το αποτέλεσμα όταν περάσουμε από κλασικές
μονάδες σε Mosaic ad-hoc battle groups.**

## Σκληροί κανόνες

- **Καμία τιμή hardcoded.** Όλες οι παράμετροι (capacities, rates, ranges, damage, HP,
  ταχύτητες) διαβάζονται από JSON config. Αν λείπει τιμή, μπαίνει placeholder στο config με
  σχόλιο `TODO`, όχι magic number στον κώδικα.
- **Γλώσσα: C++.** Αποφασίστηκε με τον επιβλέποντα (17/10/2026). Τα simulation προγράμματα
  ξοδεύουν ~90% του χρόνου στο runtime loop και το CLR της C# είναι bytecode. Μη προτείνεις
  αλλαγή γλώσσας.
- **Ξεκινάμε από τον κώδικα του επιβλέποντα** (Mars/Space Rover, C++, από το Moodle): base
  `agent` class με generic dispatch function για incoming messages, state machine design
  pattern, και το main simulation loop με event creation/dispatch. Οι δικές μας κλάσεις
  μπαίνουν **κάτω** από αυτή τη δομή, δεν την αντικαθιστούν. Αν ο κώδικας δεν υπάρχει στο
  repo, ρώτα πριν φτιάξεις δική σου δομή από το μηδέν.
- **Performance είναι first-class concern.** Κάθε build που μετράμε είναι optimized
  (`/O2` ή `-O2`). Μέτρηση χωρίς optimization δεν λέει τίποτα.
- **Incremental modelling.** Προσθέτουμε λεπτομέρεια σταδιακά και ελέγχουμε πόσος ρεαλισμός
  κερδίζεται ανά μονάδα πολυπλοκότητας. Μη προσθέτεις μηχανισμούς που δεν ζητήθηκαν.
- **Τα drones είναι τελευταία.** Ρητή εντολή επιβλέποντα — μπαίνουν στο δεύτερο simulation.
- **Mosaic είναι Φάση 3 και ΔΕΝ αγγίζεται πριν.** Καμία `MosaicUnit`, καμία
  `BattleGroup`, κανένα capability-sharing μεταξύ platforms, κανένα «να το αφήσουμε έτοιμο
  για μετά». Οι μονάδες της Φάσης 1 είναι μονολιθικές. Το Mosaic μπαίνει **μόνο** αφού το
  κλασικό simulation ολοκληρωθεί πλήρως, τρέξει, και επικυρωθεί ως μεθοδολογικά σωστό.
- **Κάθε αλλαγή ενημερώνει το `docs/CODE_ANALYSIS.txt`.** Ο χρήστης το χρησιμοποιεί για
  να απαντά σε ερωτήσεις του επιβλέποντα και να αλλάζει παραμέτρους γρήγορα. Σε κάθε
  αλλαγή κώδικα, config ή φακέλων: (α) γραμμή στο «ΙΣΤΟΡΙΚΟ ΑΛΛΑΓΩΝ», (β) ενημέρωση της
  ενότητας του αρχείου που άλλαξε (νέο αρχείο = νέα ενότητα), (γ) ενημέρωση του πίνακα
  παραμέτρων αν άλλαξε κλειδί, (δ) νέα κεφαλίδα (ημερομηνία, checksums) αν άλλαξε η
  συμπεριφορά. Εξηγεί τι κάνει κάθε αρχείο και γιατί υπάρχει, στα ελληνικά.
- **Μέθοδος υλοποίησης = skill `wargame-sim-method`** (στο `Diplomatiki/.claude/skills/`).
  Περιέχει τον κύκλο κάθε βήματος, τι ρωτάμε τον χρήστη, τις σχεδιαστικές αρχές, το
  πρόγραμμα βημάτων (pilot → Φάση 2 → Mosaic) και το στιγμιότυπο κατάστασης. Ενημέρωσε
  το `references/state-snapshot.md` του skill όταν αλλάζει κάτι σημαντικό.

## Δομή

```
docs/MODEL.md     # το μοντέλο: grid, resources, κατανάλωση, engagement, assets
docs/PILOT.md     # το τρέχον παραδοτέο: pilot benchmark, acceptance criteria
config/sim.json   # όλες οι τιμές
docs/CODE_ANALYSIS.txt   # τι κάνει κάθε αρχείο, παράμετροι, ερωτήσεις επιβλέποντα
src/              # C++ - οργανωμένο ανά ρόλο (config, world, engine, entities, ...)
                  # δες τον πίνακα "Layout" στο README.md
```

Διάβασε `docs/MODEL.md` πριν γράψεις κώδικα που αγγίζει μοντελοποίηση και `docs/PILOT.md`
πριν ξεκινήσεις task.
